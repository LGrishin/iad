# IAD — Interactive Architecture Diagram

Общий каркас для интерактивных архитектурных диаграмм. Репозиторий содержит
просмотрщик, пустой шаблон данных, схемы, правила заполнения и проверки.
Агент изучает исходники выбранного проекта, заполняет отдельный каталог данных,
а каркас проверяет его и собирает визуализацию. Готовые диаграммы в поставку не входят.
`init`, сборка и парное сравнение отклоняют каталоги данных и результата внутри
репозитория каркаса; выбирай внешнюю папку.

В просмотрщике уже есть вложенные двумерные диаграммы, масштаб и перемещение,
проигрывание сценариев с развилками и отдельным прогрессом, краткие карточки с
подробностями по нажатию, просмотр кода и сравнение версий. У источников показаны
репозиторий, точный коммит, файл и строки; доступны встроенный код и переходы к
репозиторию и файлу. В конце карточки участника и каждого шага можно скопировать
заготовку вопроса с контекстом. Тема по умолчанию — нейтральный чёрный, насыщенный
красный и небольшие матово-золотистые акценты; её можно настроить данными.

## Использование

Передай агенту путь к исходникам и точке входа каркаса:

```text
Построй IAD проекта /path/to/project.
Следуй /path/to/iad-kit/START.md.
```

Для нескольких репозиториев перечисли их пути и нужную область. Агент прочитает
[START.md](START.md), создаст пустую заготовку, проанализирует код, заполнит данные,
проверит их и соберёт карту. Существующую диаграмму можно обновить, указав её имя.
Для сравнения укажи две версии исходников.

Папку для диаграммы можно по желанию указать в запросе, например:
`Каталог диаграммы: /path/to/diagrams/my-map`. Фиксированного каталога по умолчанию
нет: если путь не указан, агент выбирает подходящую папку вне IAD Kit с учётом
рабочей области и сообщает итоговый путь. Каждая карта хранится в отдельном
каталоге и может охватывать несколько репозиториев с независимыми версиями.
Создание новой карты не перезаписывает предыдущую и не заполняет сам репозиторий
каркаса.

## Пустая заготовка и сборка

Нужны Python 3.10+ и Git. Для сборки и просмотра дополнительные Python/JavaScript
библиотеки не нужны. Из корня каркаса создай каталог данных:

```sh
python3 -m iadkit init /path/to/diagrams/my-map --repo /path/to/repository
```

`init` использует [пустой шаблон](iadkit/templates/project/), фиксирует полный Git SHA
и заполняет только служебные данные проекта. Узлы, связи, контракты, сценарии и
основания остаются пустыми. Их заполняет агент по [правилам](iadkit/spec/iad-rules.md)
и [инструкции автора](docs/authoring.md). Пустая заготовка ещё не проходит проверку
содержательной диаграммы.

После заполнения выполни:

```sh
python3 -m iadkit validate /path/to/diagrams/my-map
python3 -m iadkit build /path/to/diagrams/my-map
python3 -m iadkit preview /path/to/diagrams/my-map --port 8010
```

Открой в Chrome [http://127.0.0.1:8010/](http://127.0.0.1:8010/). Сервер
останавливается через Ctrl+C. Готовый `build/index.html` можно открыть напрямую:
карта и включённые исходники доступны без сети.

Для установленного CLI используй `iad` вместо `python3 -m iadkit`.
Установка: `python3 -m pip install -e .` (нужен setuptools).
Запуск из исходников установки не требует.

## Устройство

| Каталог | Назначение |
|---|---|
| `iadkit/assets/`, `iadkit/comparison_assets/` | Общий интерфейс, вложенные карты, проигрыватель, стрелки и сравнение |
| `iadkit/templates/project/` | Пустая авторская заготовка, используемая `init` |
| `iadkit/schemas/` | JSON Schema авторских данных и собранной модели |
| `iadkit/spec/iad-rules.md` | Единый нормативный документ с требованиями и обратной связью |
| `iadkit/` | Загрузка, проверка, сборка, снимки исходников и CLI |
| `docs/` | Заполнение данных, уровни, формат, API и развитие каркаса |
| `tests/` | Проверки на данных и Git-репозиториях, создаваемых во временных каталогах |

Сборка выдаёт `index.html`, `model.json`, `sources.json`, `manifest.json` и
`report.json` во внешнем каталоге диаграммы. Манифест фиксирует версии и контрольные
суммы входов и ядра. Одинаковые данные и исходники при той же доступности
Git/архивов дают одинаковые байты.

Сборщик проверяет происхождение текста через Git или архив; автор отдельно
подтверждает смысл утверждений по коду. Доступный файл не делает описание
автоматически проверенным. Автоматический анализ произвольного языка, запись трасс
и построение архитектуры из Git diff требуют анализа агентом или отдельных адаптеров.

Развитие каркаса и построение карты — разные задачи. Диаграмма, переданная для
обсуждения качества IAD, помогает улучшить общие правила, шаблоны и просмотрщик.
Саму карту изменяют, когда это входит в запрос пользователя. Подробнее:
[инструкции агенту](AGENTS.md), [уровни и вложенность](docs/hierarchy.md),
[формат](docs/format.md), [сравнение](docs/comparison.md), [API](docs/api.md),
[проверки каркаса](docs/development.md).
