# API карты IAD

В открытом `index.html` синхронный API доступен как `window.IAD`. Его операции читают локальную модель. Сеть и запуск изучаемого проекта не требуются. Возвращаемые структурные данные копируются и не меняют модель. Для автоматизации без DOM используйте `require('./iadkit/assets/player.js').createApi(model)` в Node.js. Модель передаётся явно; встроенной карты проекта в пакете нет.

| Операция | Вход | Результат |
| --- | --- | --- |
| `getManifest()` | Нет | Манифест выбранной версии |
| `getScenarios({scope}?)` | Необязательная область: `null` для обзора или ID узла | Каталог сценариев с полями `{id, title, goal, entry, mode}` и заданными `scope`, `trigger`; без аргумента — полный каталог |
| `resolveTarget(query)` | Непустая строка: ID или часть имени, без учёта регистра | `{status, candidates:[{id,label}]}`. `status`: `resolved`, `ambiguous`, `not-found` |
| `getChildren(id = null)` | ID узла; `null` для обзорного уровня | Непосредственные дочерние узлы |
| `getEdges(id?)` | Необязательный ID узла | Все направленные связи либо связи с данным концом. Без неявного обхода потомков |
| `getSteps(scenarioId, choices = {})` | ID сценария; словарь `{stepId: optionId}` | Выбранный путь от входа до конца или первой развилки без решения, включая саму развилку |
| `getOptions(scenarioId, stepId)` | ID сценария и его шага | Массив вариантов `{id,label,condition,result,next}`; `[]` для обычного шага |
| `buildSnapshot(target = manifest.target.id)` | Точный ID репозитория или узла | Детерминированный снимок: манифест, узлы, связи, контракты, сценарии, доказательства |
| `compareSnapshots(before, after)` | Два снимка одного таргета | `{before,after,changes,scenarios}`; архитектурные изменения и первое расхождение каждого маршрута |

`buildSnapshot` для узла включает его потомков, связи с хотя бы одним включённым концом и полные сценарии с хотя бы одним включённым участником. Контракты включают собственные контракты узлов и все контракты, явно используемые включёнными связями и сценариями через `contracts`, `sourceContract` или `targetContract`. Это позволяет сохранить контекст взаимодействия с соседями. Передавайте точный ID из `resolveTarget`; неоднозначное имя не выбирается автоматически.

`compareSnapshots` сопоставляет устойчивые ID. В `changes` используются `kind: nodes | edges | contracts | scenarios` и `status: added | removed | changed`. Для сценариев статус — `same | changed | added | removed`. `firstDivergence` содержит порядковое место обхода, старый и новый шаг с ключом ветки, структурированными решениями `choices` и явно используемыми контрактами. Сравниваются действия, данные, результаты, условия, порядок и гарантии. Изменение одного SHA, номера строки или ссылки без изменения описанной семантики расхождением не считается. Значимые гарантии контракта влияют на шаги, где его ID явно указан в `contracts`, `sourceContract` или `targetContract`.

При изменении линейного продолжения первое расхождение указывает на первое различающееся действие; ссылки `next` определяют обход, а их изменения также остаются в `changes`. Первое расхождение ищется от точки входа, затем рекурсивно по вариантам в порядке массива `options`; каждая ветка сравнивается отдельно. Это порядок представления, а не временная последовательность альтернативных исходов. Совпадение двух снимков означает совпадение представленных описаний; оно не доказывает эквивалентность исходного кода вне модели.

Общие продолжения сходящихся веток сравниваются без перечисления всех возможных
путей. `firstDivergence.ordinal` сохраняет место в полном обходе: это число до
`Number.MAX_SAFE_INTEGER` включительно и десятичная строка для больших значений.
Это позволяет точно указать расхождение после большого общего подграфа.

Снимок можно сохранить кнопкой интерфейса и загрузить в сравнение. При импорте одного JSON-снимка основания старого шага берутся из `snapshot.evidence`; полный текст его исходников автоматически не добавляется. Команда `iad compare` собирает две обычные модели вместе с обеими коллекциями исходников и предоставляет общий экран просмотра; см. [сравнение](comparison.md).

## Ошибки

У каждого узла `role` содержит краткое объяснение в одном-двух предложениях, а `details` — подробности. `ownedData` содержит отдельные элементы `{name,type,description,details?,sources,target?}`: короткое назначение поля отделено от пояснения типа, владения и жизненного цикла. `ownershipNote` поясняет границы владения, в том числе у групп, интерфейсов и объектов с заимствованными ссылками. `sources` — ID подтверждений; `target` — ID связанного участника карты. `typeExplanations` содержит определения `{name,description,details?,sources}`. У контракта каждая запись `operations` описывает одну операцию: `{name,description,details?,input,output,errors,sources}`. В карточке краткое описание служит заголовком раскрытия; параметры, ограничения и код видны после нажатия. Пояснения загружаются из канонических авторских JSON; пути и SHA-256 этих файлов перечислены в `manifest.inputs`. Поля входят в сравнение снимков и не заменяются одной сигнатурой.

Операции выбрасывают `IadError` с полями `code`, `message` и необязательным `details`.

| Код | Условие |
| --- | --- |
| `INVALID_ARGUMENT` | Пустой или нестроковый поисковый запрос; нечисловой индекс перемотки проигрывателя |
| `NOT_FOUND` | Неизвестный ID узла, сценария или шага |
| `INVALID_CHOICE` | Недопустимый вариант текущей развилки или выбранного пути |
| `INVALID_PATH` | Шаг существует, но не лежит на пути с переданными решениями |
| `INVALID_MODEL` | Путь ссылается на отсутствующий шаг |
| `CYCLE` | Сценарий содержит цикл вместо конечного объясняющего маршрута |
| `INVALID_SNAPSHOT` | Нет обязательных коллекций снимка; маршрут ссылается на отсутствующий шаг или контракт |
| `TARGET_MISMATCH` | Разные таргеты снимков |

Не найденное или неоднозначное имя `resolveTarget` возвращается результатом с кандидатами, а не исключением. Входные JSON-файлы должны соответствовать схеме создаваемого снимка; это API доверенной модели диаграммы, а не валидатор произвольных документов.

## Пример

```js
const scenarios = IAD.getScenarios();
const steps = IAD.getSteps(scenarios[0].id);
const fork = steps.find(step => step.branch);
const options = fork ? IAD.getOptions(scenarios[0].id, fork.id) : [];
const snapshot = IAD.buildSnapshot();
const comparison = IAD.compareSnapshots(snapshot, snapshot);
// Все comparison.scenarios имеют status === 'same'.
```

`window.IADViewer.getState()` возвращает копию состояния интерфейса для проверки: текущий сценарий, шаг, индекс, подтверждённые решения, открытый вариант, состояние воспроизведения, раскрытые узлы и камеру. Это вспомогательный интерфейс проверки, отдельно от API модели.


## Управление локальным просмотром

`window.IADViewer.navigateTo({scenario, stepId?, choices?, inspect?})` ставит просмотр
на паузу, выбирает сценарий и шаг, раскрывает родителей участников и показывает
путь. По умолчанию `stepId` — вход сценария, `choices` — пустой объект. `inspect`
открывает карточку указанного узла. Решения и достижимость проверяются до изменения
состояния: неверный запрос оставляет навигацию прежней. Результат — новое состояние
просмотра. Метод не выполняет операции изучаемого проекта.

`window.IADViewer.openSource(evidenceId)` открывает встроенный код по ID основания
данной версии; неизвестный ID вызывает `NOT_FOUND`. `getState()` дополнительно
возвращает вкладку подробностей `tab` и ID рассматриваемого узла `inspected`.

Парный просмотрщик использует эти методы для перехода к первому расхождению и
открытия кода двух ревизий. Доступная схема состояний описана в `docs/comparison.md`.


`window.IADViewer.selectScenario(id)` переключает сценарий с сохранением его
прежнего шага и решений. Событие окна `iad-view-change` после обновления интерфейса
содержит копию состояния в `event.detail`; парный просмотр использует его для
согласования общего селектора со списками сценариев внутри каждой карты.


## Области каталога

`IAD.getScenarios()` сохраняет полный каталог. `IAD.getScenarios({scope: null})`
возвращает обзорные сценарии, а `{scope: nodeId}` — собственные/дочерние сценарии
области и относящиеся к ней родительские маршруты. `scope` и `trigger` присутствуют
в каталоге, если заданы моделью. Неизвестная область вызывает `NOT_FOUND`.

`IADViewer.setScope(nodeId | null)` меняет контекст просмотра без перемотки текущего
маршрута. `getState()` содержит `scope`, `visibleScenarios` и `routingDiagnostics`.
`getLayout()` возвращает копии геометрии карточек и размеров карты для проверки.
Явный переход к сценарию другого уровня раскрывает подходящий контекст; автоматические
шаги и раскрытие концов связи не меняют область каталога.


`IADViewer.getPorts()` возвращает копию рассчитанных точек подключения: устойчивый
`id`, видимый `node`, настоящий владелец маркера `owner`, предоставляющий API
`contractOwner`, `kind` (`provided`, `required`, `connection`),
ID `contract` либо `null`, сторону и геометрию. Это диагностическое API просмотрщика,
а не вызов изучаемой системы. Для неописанного контракта `connection` не означает
наличия публичного API в исходниках. Точки пересчитываются при раскрытии границ,
а идентичность известных контрактов сохраняется при переключении шагов.
